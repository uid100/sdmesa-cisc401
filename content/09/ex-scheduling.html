Hospital Staff Scheduling Database Project

You have been hired as a database analyst for a regional hospital. Your task is to design, create, populate, and query a relational database that supports hospital staff scheduling across multiple departments operating 24 hours per day.

This project is intended to simulate a realistic database development process. The project is divided into three phases, and each phase requires a deliverable. Waiting until the final week will make successful completion difficult.

Learning Objectives

  • Design a normalized relational database.
  • Create tables using SQL.
  • Define primary key and foreign key relationships.
  • Populate a database with realistic sample data.
  • Write multi-table queries using JOIN operations.
  • Use filtering, sorting, aggregates, and grouping.
  • Create meaningful management reports from database data.

Database Requirements

Required Tables

  1. Department
  2. Employee
  3. Shift
  4. Schedule

Suggested Columns

Department

  • department_id (Primary Key)
  • department_name

Employee

  • employee_id (Primary Key)
  • first_name
  • last_name
  • job_title
  • department_id (Foreign Key)

Shift

  • shift_id (Primary Key)
  • shift_name
  • start_time
  • end_time

Schedule

  • schedule_id (Primary Key)
  • employee_id (Foreign Key)
  • department_id (Foreign Key)
  • shift_id (Foreign Key)
  • shift_date

Minimum Data Requirements

  • 7 departments
  • 40 employees minimum
  • At least 10 physicians
  • At least 20 nurses
  • At least 10 additional staff members (technicians, therapists, clerks, coders, etc.)
  • 3 shifts per day
  • 7 consecutive days of scheduling data
  • At least 120 schedule assignments

The purpose of these requirements is to create enough data for meaningful reporting and query testing.

Business Rules

  1. Every employee must belong to a department.
  2. Every schedule assignment must reference an existing employee.
  3. Every schedule assignment must reference an existing department.
  4. Every schedule assignment must reference an existing shift.
  5. Each department must have multiple employees assigned throughout the week.
  6. Create at least three intentional scheduling conflicts for testing purposes.

Required Query Reports

Query 1: Department Schedule Report

Display all employees scheduled within a department.

  • Employee Name
  • Job Title
  • Department Name
  • Shift Name
  • Shift Date

Query 2: Employee Weekly Schedule

Display the complete weekly schedule for a selected employee.

Query 3: Staffing Levels Report

Display the number of employees assigned to each department and shift using COUNT() and GROUP BY.

Query 4: Scheduling Conflict Report

Identify employees who have overlapping or conflicting assignments.

Query 5: Department Staffing Summary

Display the total number of employees assigned to each department.

Query 6: Employee Workload Report

Display the number of scheduled shifts worked by each employee during the week.

Project Milestones and Deliverables

Week 1 Deliverable: Database Structure

  • Create the database and all required tables.
  • Define primary keys and foreign keys.
  • Submit a single SQL script that creates the database and all tables.
  • The script must execute successfully without manual editing.
  • Test your script using localhost\SQLEXPRESS or an equivalent SQL Server environment before submission.

Submit: CreateDatabase.sql

Week 2 Deliverable: Seed Data

  • Populate all tables with realistic hospital data.
  • Meet all minimum data requirements.
  • Verify that foreign key relationships are satisfied.
  • You may revise your Week 1 script if design improvements become necessary.

Submit:

  • CreateDatabase.sql (updated version)
  • InsertData.sql

Week 3 Deliverable: Final Submission

Submit the final version of your project including all scripts required to rebuild and test the database.

Submit all eight SQL files:

  1. CreateDatabase.sql
  2. InsertData.sql
  3. DepartmentSchedule.sql
  4. EmployeeWeeklySchedule.sql
  5. StaffingLevels.sql
  6. SchedulingConflicts.sql
  7. DepartmentStaffingSummary.sql
  8. EmployeeWorkloadReport.sql

Each query file must execute independently and produce the requested report.

Submission Expectations

  • SQL should be properly formatted and readable.
  • Meaningful aliases should be used in query output.
  • Scripts should include comments where appropriate.
  • All scripts should execute without errors.
  • Your database should contain realistic and believable hospital data.
  • All work must be your own.
